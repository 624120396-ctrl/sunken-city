# 房间系统视觉彻底重构方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` or `superpowers:subagent-driven-development` when implementing this plan task-by-task. This plan is visual/product-UX first. Unless the user explicitly asks, do not run deep E2E, full Playwright regression, full visual regression, or production deployment.

**日期：** 2026-07-05  
**项目：** 沉没之城 / Sunken City  
**范围：** 房间详情页、房间内聊天、成员侧栏、KP 工作台、PL 参与端、观察者只读态、房间调查工作台视觉系统。  
**当前优先级调整：** 用户已明确判断当前房间详情页视觉不合格，因此本方案将“房间系统视觉重构”提升为当前 UI/UX P0。该优先级覆盖旧文档中“房间页后置”的执行顺序，但不改变后端、Socket、骰点、战斗、私聊和生命周期边界。

---

## 1. 结论

房间详情页不能继续在现有深色控制台上做局部补丁。

下一阶段应进行一次“产品界面级视觉重构”：

1. 以浅色跑团舞台为主，不再用大面积深色/黑色压住页面。
2. 聊天区作为核心阅读区，优先保证长期可读。
3. KP、PL、OBSERVER 三种体验分层，而不是所有工具挤在同一舞台。
4. 房间调查工作台从“横向深色条”改为真正的档案工作区。
5. 装饰纹理必须服务信息层级，不能像 AI 背景或素材堆叠。
6. 只做轻量验证；当前不需要深度测试。

## 2. 产品目标

房间页是《沉没之城》的核心跑团现场，不是普通后台页面，也不是静态概念海报。

成功标准：

- KP 能在 PC 上主持，不迷失在工具里。
- PL 能在移动端优先聊天、骰点、看自己角色状态。
- OBSERVER 明确知道自己是只读观看者。
- 长时间跑团时，聊天和正文不造成视觉疲劳。
- 页面一眼有“明亮深海秘仪档案馆”的气质，但操作仍像成熟产品 UI。

## 3. 用户与主任务

| 身份 | 设备 | 主任务 | 视觉/交互重点 |
| --- | --- | --- | --- |
| KP / 主持人 | PC | 主持、发言、掷骰、管理场景/线索/NPC/战斗/私聊/结算 | 高密度但分区清楚，工具区强但不压主舞台 |
| PL / 调查员 | 手机、PC | 读聊天、发言、骰点、看自己角色状态 | 聊天优先、输入稳定、工具少打扰 |
| OBSERVER | 手机、PC | 观看公开内容 | 只读身份明确，无误导按钮 |
| NON_MEMBER | 手机、PC | 判断能否加入或旁观 | 清楚的加入/申请/无权限状态 |

## 4. 视觉方向

### 4.1 场景句

用户像坐在一张被深海日光照亮的调查桌前，桌面是浅色档案纸、湿润石材和氧化铜边框；黑暗在远处和工具边缘，不压在正文上。

### 4.2 色彩策略

采用 **Restrained + 局部 Committed**：

- 主舞台：浅色档案纸、浅色湿石、冷雾白灰。
- 结构边缘：氧化铜、旧金细线。
- 工具层：暗釉石材、深海青黑，但不纯黑。
- 危险语义：血红，只用于战斗、理智、不可逆操作、结算终态。

明确排除：

- 紫粉色科技感。
- 黑色透明卡片作为主内容。
- 大面积深绿黑舞台。
- 大面积血红恐怖背景。
- 无意义金箔纹路堆叠。
- 低透明金色正文。
- 依赖全局黑幕保证可读性。

## 5. 房间页信息架构

### 5.1 PC / KP 房间结构

```text
--------------------------------------------------------------------+
| 房间顶栏：返回 / 房间名 / 生命周期 / 当前身份 / 关键操作            |
+------------------+--------------------------------+----------------+
| 成员与状态栏       | 跑团主舞台                       | KP 工作台       |
|                  |                                |                |
| KP / PL / OBS    | 当前场景 / 公告 / 焦点             | 标签：          |
| 角色绑定          | 聊天与骰点记录                    | 成员            |
| HP / MP / SAN    | 输入区 / 快捷骰                   | 场景            |
| 生命周期提示       |                                | 线索            |
|                  |                                | NPC             |
|                  |                                | 战斗            |
|                  |                                | 私聊            |
|                  |                                | 结算            |
+------------------+--------------------------------+----------------+
```

设计重点：

- 中央舞台必须是浅色阅读区。
- KP 工具台可以深，但要像“仪器柜/档案抽屉”，不是黑色按钮塔。
- 成员栏是状态摘要，不是聊天室的视觉竞争者。
- 调查工作台应进入 KP 工作台或舞台上方的轻量焦点区，不应成为大面积横幅。

### 5.2 PC / PL 房间结构

```text
+--------------------------------------------------------------------+
| 房间顶栏：房间名 / 生命周期 / 自己身份 / 报告入口                    |
+------------------+--------------------------------+----------------+
| 自己角色状态       | 跑团主舞台                       | 参与工具        |
| 成员摘要           | 聊天与骰点记录                    | 线索            |
|                  | 输入区 / 快捷骰                   | 报告            |
|                  |                                | 房间信息        |
+------------------+--------------------------------+----------------+
```

设计重点：

- PL 不需要常驻完整 KP 工具。
- 自己角色状态优先于全员管理。
- 旁支工具收纳，不挤压聊天主舞台。

### 5.3 移动端 / PL 结构

```text
+------------------------------+
| 房间名 / 生命周期 / 身份       |
+------------------------------+
| 自己角色状态 HP MP SAN         |
+------------------------------+
| 聊天与骰点记录                 |
|                              |
|                              |
+------------------------------+
| 输入框 / 发言 / 骰点           |
+------------------------------+
| 底部栏：聊天 / 角色 / 成员 / 更多 |
+------------------------------+

更多 Sheet:
+------------------------------+
| 线索 / 日志 / 房间信息 / 报告   |
| 仅展示当前身份允许访问的内容    |
+------------------------------+
```

设计重点：

- 手机不是 PC 三栏缩小版。
- 聊天和输入区必须稳定。
- 工具进入底部 sheet。
- 触摸目标不小于 48px。

### 5.4 OBSERVER 结构

```text
+-------------------------------------------+
| 观察者提示：你正在观看公开内容              |
+-------------------------------------------+
| 公开场景 / 公开聊天 / 公开骰点 / 公开报告摘要 |
+-------------------------------------------+
| 无发言、无战斗控制、无结算控制、无 KP 工具   |
+-------------------------------------------+
```

设计重点：

- 只读态不是残缺态。
- 不显示会误导权限的按钮。
- 公开内容可读，私密内容不占位、不泄露。

## 6. 视觉骨架

### 6.1 RoomShell

职责：

- 页面背景、房间顶栏、生命周期、身份提示、整体响应式。

视觉：

- 背景保留深海城市和冷雾，但降低对主内容的影响。
- 顶栏可以是暗釉石材/氧化铜，但高度要克制。
- 不使用全局黑幕。

### 6.2 RoomStage

职责：

- 当前场景、聊天记录、骰点记录、输入区、快捷骰。

视觉：

- 主背景使用 `archive` 或 `limestone`。
- 聊天内容像“调查记录”，不是深色泡泡。
- 空状态应有轻量档案纸提示，不使用居中黑暗大幕。

### 6.3 RoomChatTranscript

职责：

- 展示聊天、系统消息、骰点消息、KP 消息、自己消息。

视觉与规则：

- 普通发言：浅纸面记录条，正文深墨色。
- KP 发言：同样可读，但带更清晰的角色标识或铜/血红小标。
- 自己消息：不依赖靠右气泡，改用轻微纸色/边框差异。
- 骰点：用结构化结果块，不混成普通文本。
- 系统消息：像档案注记，不像弹幕。
- 长文本行宽控制在 65-75ch。
- 字号默认 15-16px，行高 1.6-1.75。

### 6.4 RoomChatComposer

职责：

- 输入、发送、快捷短语、公开骰/秘密骰、移动端快捷骰入口。

视觉：

- 底部是浅色纸面/石面工具条。
- 发送按钮旧金 + 暗血红尾色。
- 危险工具如“理智侵蚀”使用血红语义。
- 移动端输入区固定、可触、不过度装饰。

### 6.5 RoomParticipantRail

职责：

- 成员、角色、HP/MP/SAN、绑定状态、观察者状态。

视觉：

- PC 侧栏可以浅色或中性色，不再整块黑绿。
- 数据要清楚，尤其 HP/MP/SAN。
- 收起态保留头像和状态点。
- KP 可编辑状态应明确，但不要像后台表单。

### 6.6 KpWorkbench

职责：

- 成员管理、场景、线索、NPC、骰点、战斗、私聊、结算入口。

视觉：

- 右侧可使用深色材质，但不纯黑。
- 标签页和工具分区清楚。
- 危险/不可逆操作分离到单独区域。
- 不允许 KP 工具覆盖聊天主阅读区。

### 6.7 PlayerConsole

职责：

- PL 当前角色、快捷骰、个人状态、允许访问的线索/报告。

视觉：

- 移动端优先作为底部 sheet 或顶部摘要。
- PC 上可作为轻量右栏或侧栏摘要。

### 6.8 ObserverConsole

职责：

- 观察者身份提示、公开内容入口、只读说明。

视觉：

- 简洁、低干扰。
- 不把无权限按钮展示成灰掉的“坏掉界面”。

## 7. 材质与 token 策略

现有纹理 token：

- `--coc-texture-archive-paper`
- `--coc-texture-pale-limestone`
- `--coc-texture-oxidized-copper`
- `--coc-texture-sea-mist`
- `--coc-texture-header-cold-mist`
- `--coc-texture-dark-glazed-stone`
- `--coc-texture-antique-gold-thread`
- `--coc-texture-gold-vertical-sigil`
- `--coc-texture-gold-sunburst-arc`
- `--coc-texture-gold-crescent-index`
- `--coc-texture-gold-empty-state`

房间页重构应优先复用这些 token。若现有素材不够，应先写资产规格卡，再用内置 image2 生成。

新增建议：

```css
--room-surface-stage: 明亮档案纸/湿石;
--room-surface-toolbar: 暗釉石材/氧化铜;
--room-surface-note: 档案纸记录条;
--room-ink-primary: 深墨色;
--room-ink-secondary: 深灰褐;
--room-accent-copper: 氧化铜;
--room-accent-gold: 旧金;
--room-accent-blood: 血红;
```

注意：

- 不把页面视觉继续散落成随机 `rgba()`。
- 不把材质硬写进每个组件。
- 不再以 `bg-black/20` 作为默认高级感。

### Phase 4：移动端 / PL 参与端

目标：

- 手机房间页不是 PC 缩小版。

任务：

验收：

- 375px 无横向滚动。

### Phase 5：OBSERVER / NON_MEMBER 状态

目标：

- 只读和无权限状态清楚、体面。

任务：

- 新建无权限/只读视觉状态。

验收：

- OBSERVER 明确知道自己能看什么、不能做什么。
- NON_MEMBER 明确看到加入/申请路径或无权限说明。

- 删除或隔离旧黑色控制台补丁。

任务：

验收：

## 11. 视觉验收标准

### 11.1 必须达成

- 第一眼不再是深色控制台。
- 主舞台以浅色为主。
- 聊天区长期可读。
- KP 工具和主舞台分区明确。
- 手机 PL 主任务明确。
- 纹理有材质感，但不遮挡正文。
- 血红只用于危险、战斗、理智和不可逆操作。
- 金色用于结构和主操作，不做低透明正文。

### 11.2 明确不合格

- 大面积暗绿黑。
- 主区域继续是黑色透明卡片。
- 聊天气泡可读性差。
- 工具按钮像科技控制台。
