## 2. 项目北极星

《沉没之城》不是普通论坛、角色卡工具或暗色恐怖主题后台。

它的目标形态是：

> 一个适合长期 CoC 跑团的深海秘仪档案馆：KP 能稳定主持，PL 能顺畅参与，团后能沉淀案件、角色、报告、社区记忆和世界观收藏。

产品成功标准：

- 跑团过程中，用户能清楚知道“我是谁、我在哪个房间、现在能做什么”。
- KP 在 PC 上能管理成员、场景、线索、NPC、骰点、战斗、结算和报告，而不被界面拖慢。
- PL 在移动端优先完成聊天、骰点、查看角色状态、理解当前目标。
- 观察者只读边界清晰，不误触操作。
- 长期玩家愿意留下角色经历、调查报告、收藏、印记、位阶和社区讨论。
- 视觉精致、明亮、自然，避免廉价黑幕、灰底灰字和低透明金色正文。

## 5. 总体优先级

### P0：生产稳定、权限保护与语音验收收口

保持版本化发布、房间权限、暗骰脱敏、语音令牌与 LiveKit/coturn 健康；待 Codex Chrome bridge 恢复后补做双浏览器真人听感验收。

原因：

- 房间、调查、招募和语音均已进入真实生产，权限与发布回归的成本高于继续扩功能。
- 语音真人验收延后是工具环境缺口，不应阻塞其他产品开发，也不应误写成已通过。
- 后续 VTT 必须作为可选视觉层接入，不能反向改写房间权威数据。

### P1：VTT 调查场景 MVP

第一阶段只做“COC 调查场景板”，按以下依赖顺序推进：

1. 私有素材资产库 V1：只读扫描、分类、缩略图、来源记录、私有代理和审核状态。
2. RoomScene 背景与 marker 点位 V1：场景背景、点位、PL 可见性和当前场景切换。
3. TokenAsset / SceneTokenInstance 绑定 V1：素材、场景实例和 NPC/角色等领域实体分层绑定。
4. RuleSystemManifest / RuleRegistry V1：只提供规则包 manifest、注册与启用边界，不实现完整 DND5E。
5. FVTT / Roll20 只读 pack adapter V1：抽样识别用户私有包并生成素材与场景预设草稿，不自动公开。

原因：

- 地图、场景和 Token 是 KP 备团与玩家空间感的高频痛点，但现有调查档案仍应保持权威。
- 私有资产库是后续地图、Token 和商业资源包导入的共同底座，必须先于画布开发。
- 开始实施计划前必须锁定：规则按 room 还是 scenario 启用、坐标模式、public 可见性语义、私有存储位置和视频代理策略，并抽样检查用户真实 FVTT/Roll20 包结构。

### P2：开团增长、新人引导与剩余入口收口

包括招募板 V1.1、新人角色分流指南、首页/故事书入口和全局导航收口；这些工作可以与 VTT 后端资产层并行，但不得同时修改同一房间 UI Shell。

原因：

- 招募和帮助已经上线，下一轮收益来自过期提醒、收藏筛选、排期确认和上下文式新人引导。
- 首页与故事书入口应在 VTT 路由和导航归属明确后再收口，避免二次调整。

### P3：AI 副手与素材工坊

AI 只做副手，不做 KP，不自动公开，不改状态。当前阶段只保留骨架和登记能力，展示层留空；真实付费调用另行确认。

首轮 AI 内容：

- DeepSeek V4 / V4.1 Flash：长上下文整理、摘要、结构化提取、公开摘要。
- Doubao-Seed-Character：NPC 口吻、角色化文本、招募文案、氛围描述。
- Seedream 4.5：NPC 头像、场景图、旧照片、报纸剪报、handout、神秘符号。
- AI 语音模型、TTS、STT、实时语音代理仅预留，不接入；真人房间语音另走“房间实时语音频道 V1”专项。

### P4：长期留存、世界观与游戏化模块

包括黑水港、溺者之牌、无名集市、位阶、印记、收藏、论坛、个人资料和角色档案增强。

原因：

- 这些模块决定长期留存和世界观厚度。
- 但它们不应抢在跑团核心之前。

## 6. 迭代主线

### 主线 A：跑团核心稳定

目标：把房间从“可用”升级为“长期可主持、可复盘、权限清晰”。

里程碑：

- A1：整理房间契约文档，统一生命周期命名，以已上线契约为准。
- A2：房间页逐步围绕 `myRole`、`myCapabilities`、`myBinding`、`lifecycle` 渲染。
- A3：保持 KP / PL / OBSERVER / NON_MEMBER 行为边界稳定。
- A4：结算和报告继续只做已上线链路维护，不扩写官方规则成长。

验收：

- 前端不再从 `isCreator` 猜 KP 权限。
- 已结团 / 已取消房间不会误开放普通写操作。
- 非成员不能读取报告和结算敏感信息。

### 主线 B：调查体验升级

目标：让每个房间沉淀为一个案件档案，而不是只依赖聊天流。

当前状态：

- Phase 1 调查档案系统 V1 已由调查体验线程完成并收口。
- Phase 2 团前 / 团后连续性已完成基础能力。
- Phase 3 线上参与焦点已完成基础焦点条。
- Phase 4 低成本效率工具已完成重要消息归档、关键骰点归档、报告增强和只读角色状态同步检查。
- Phase 6 房间沟通队列已完成。
- Phase 7 招募资料 / 申请基础、邀请 / 审批加入闭环已完成。
- 运营总览、房间列表摘要、通知、招募风格匹配、开团准备度、角色房间经历、消息中心通知元信息、报告归档和调查计数已完成。
- 后续重点不再是继续扩写线索板或重复做协作功能，而是交给 UI/UX 线程统一视觉表现；AI 前置骨架保留但展示留空。

里程碑：

- B1：调查档案 V1：线索、NPC、场景、调查日志、KP 私密便签。状态：已完成。
- B2：团前 / 团后连续性：备团中心、上次回顾、当前目标、未解决问题。状态：已完成基础版。
- B3：PL 当前焦点：当前位置、当前目标、最新线索、关键骰点、当前场景摘要。状态：已完成基础版。
- B4：报告增强：从调查日志生成更可读的团后档案。状态：已完成基础版。
- B5：与开团协作系统衔接：通知、招募、准备度、角色经历和报告归档进入房间入口、列表、消息中心和归档视图。状态：已完成基础版。
- B6：UI/UX 承接：把上述能力整理成 PC KP 可扫描、移动端 PL 优先的界面。状态：下一步。

验收：

- KP 能创建、公开、隐藏线索和 NPC。
- PL / OBSERVER 只能看到公开内容。
- 场景切换和关键公开事件自动进入调查日志。
- KP 私密便签不会进入公开报告。

### 主线 C：开团协作与社区招募

目标：降低鸽团、改期、凑人难、风格不匹配和新手迷路。

当前状态：基础能力已由调查体验线程完成，后续重点是 UI/UX 统一表现和必要的窄范围打磨。

里程碑：

- C1：房间邀请、下次开团时间、参加确认、请假和待定。状态：基础版完成。
- C2：站内通知：公告、改期、邀请、确认提醒。状态：基础版完成。
- C3：招募页：风格标签、人数、时间、新手友好程度、报名说明。状态：基础版完成。
- C4：玩家申请与 KP 审核。状态：基础版完成。
- C5：新手 PL 小抄与 KP 开团检查清单。状态：开团准备度基础版完成，是否继续扩展由后续产品计划决定。
- C6：UI/UX 承接：统一房间列表、房间入口、消息中心和招募流程的可读性。状态：下一步。

验收：

- 房间入口能显示下一次开团时间和未确认人数。
- PL 可以确认参加、请假或待定。
- KP 可以筛选风格匹配的玩家。

### 主线 D：房间实时语音频道

目标：在不改聊天、骰点、战斗、私聊、生命周期和结算核心契约的前提下，为房间提供轻量真人语音频道。

当前状态：

- 语音可行性研报已完成。
- 推荐技术路线为 WebRTC + LiveKit + TURN/coturn。
- 香港服务器约 35ms 延迟对语音不是主要风险；后续重点应验证 UDP 稳定性、晚高峰抖动、TURN 中继比例和出站带宽。
- 启动条件：房间移动端专项完成，非房间全站 UI/UX 统一完成。

里程碑：

- D1：语音网络与部署预研：确认 LiveKit / TURN 部署、端口、域名、TLS、带宽和监控。
- D2：后端语音 token API：复用 `myRole`、`myCapabilities`、`myBinding`、`lifecycle` 鉴权，只签发 token，不处理音频流。
- D3：房间语音设置：启用开关、观察者是否可说话、KP 控场权限。
- D4：前端最小语音面板：加入 / 离开、开关麦、正在说话、网络状态、断线重连。
- D5：KP 控场能力：静音成员、全员静音、移出语音。
- D6：移动端入口：放入底部抽屉，不抢聊天首屏。

边界：

- 不做录音。
- 不做语音转文字。
- 不做 AI 总结。
- 不做跨房间语音大厅。
- 不做语音社交广场。
- 不改 Socket 聊天、骰点、战斗、私聊、生命周期或结算核心。

验收：

- 4-6 人同房间语音 2 小时基本稳定。
- 晚高峰和移动网络至少各做一次轻量真实测试。
- KP 能控场。
- 掉线能重连。
- 文字聊天、骰点、线索、生命周期不受影响。

### 主线 E：AI 副手系统

- D5：Seedream 4.5 素材工坊：生成 NPC 头像、场景图、handout 等私密草稿。
- D6：KP 私密提醒：线索遗漏、沉默玩家、节奏推进和氛围建议。

验收：

## 9. 验收矩阵

### 产品验收

- KP 能主持更轻松。
- PL 能更快知道当前目标。
- 观察者只读边界清晰。
- 长团断档恢复成本降低。
- 招募和排期降低鸽团风险。
- AI 减轻整理负担，但不替代人。
- 真人语音频道能降低跑团现场沟通成本，但不替代文字记录、骰点和调查档案。

### 技术验收

- 后端权限以 capability 为准。
- 前端不从局部状态猜权限。
- 关键写操作有生命周期限制。
- AI 有上下文过滤和用量审计。
- 数据库迁移可回滚、可解释。
- 语音媒体流不进入 Express / Socket.io 主进程，不把高频在线状态写入 SQLite。

### UI/UX 验收

- 21:9 超宽屏不挤在中间小列。
- 16:9 桌面可扫描。
- 笔记本屏幕不堆叠过密。
- 移动端 PL 首屏优先聊天、骰点、状态、目标。
- 相邻卡片不贴成黑条。
- 正文可读性优先于氛围。

### 运维验收

- 正确生产服务器是 `64.90.30.232`。
- 线上入口是 `https://coc.city/`。
- 部署前备份。
- 部署后只做窄范围验证，除非用户要求深测。
- 生产写入型冒烟必须先确认。

## 10. 风险清单

### 风险 1：计划过大，一次性开工

控制：

- 本文只作为总纲。
- 每个阶段必须拆成独立计划。
- 每个独立计划只做一个可验收目标。

### 风险 2：房间权限回归

控制：

- 继续使用 `myRole`、`myCapabilities`、`myBinding`、`lifecycle`。
- 禁止从 `isCreator` 推断关键权限。
- 写操作必须后端校验。

### 风险 3：UI/UX 提前重构导致返工

控制：

- 功能结构稳定前，只做最小可用 UI。
- 全面视觉重构放在关键功能结构之后。
- UI/UX 线程只改表现层，业务边界由功能线程确认。

### 风险 4：AI 泄密或越权

控制：

- 先做上下文过滤器。
- AI 输出默认草稿。
- PL 摘要只能读公开或自己可见内容。
- KP 私密便签、未公开线索和未公开场景禁止进入公开 AI 上下文。

### 风险 5：AI 成本失控

控制：

- DeepSeek / Doubao / Seedream 都进入用量审计。
- 房间级和用户级额度。
- 真实付费调用前必须确认。
- AI 语音大模型首轮不接。

### 风险 5.5：真人语音网络质量不稳定

控制：

- 初版采用 WebRTC + LiveKit，不自研媒体层。
- 准备 TURN / coturn 作为连接兜底。
- 先做香港 UDP、晚高峰、移动网络和 TURN 中继比例验证。
- 初版不做录音、转写、AI 总结或跨房间语音大厅。
- 成功标准以 4-6 人真实房间 2 小时稳定语音为准。

### 风险 6：官方规则误实现

控制：

- 结团后角色成长继续冻结。
- 官方规则书相关自动化必须等用户提供规则材料。
- 当前只做角色档案展示和经历沉淀。

### 风险 7：多线程互相覆盖

控制：

- 每次开工先看 `git status --short --branch`。
- 不回滚他人改动。
- 线程交接写清真实仓库、分支、文档、边界和未提交状态。
- `outputs/` 不提交。

## 11. 下一步建议

最合适的下一步是为“私有素材资产库 V1”制定独立实施计划。VTT 研究已经完成并合并，不再重复调研 Foundry 类系统，也不直接从地图画布或动态 Token 开工。

> 私有素材资产库 V1：为 KP 提供本地/私有地图、Token、handout 和场景素材的只读扫描、分类、缩略图、来源记录、私有代理与审核能力，作为后续 RoomScene 和 Token 绑定的共同底座。

原因：

- 当前房间、调查、招募、UI/UX 和语音基础已经可用，下一项明显缺口是 KP 对地图、Token 和 handout 的私有整理能力。
- 资产库先行可以避免 RoomScene、Token 和资源包导入分别重复实现存储、缩略图、来源和权限。
- 该切片不依赖官方成长规则，也不需要改 Socket、骰点、战斗、生命周期或结算核心契约。

推荐拆分：

1. 决定规则启用粒度：room 或 scenario。
2. 决定场景坐标模式和 `public` 可见性语义。
3. 决定服务器私有存储位置与访问代理边界。
4. 决定视频素材的首轮代理策略。
5. 抽样检查用户真实 FVTT/Roll20 包结构。
6. 写出私有素材资产库 V1 的数据模型、接口、权限、缩略图任务、错误处理与窄验证计划。
7. 单独实现并验收资产库，再进入 RoomScene。
