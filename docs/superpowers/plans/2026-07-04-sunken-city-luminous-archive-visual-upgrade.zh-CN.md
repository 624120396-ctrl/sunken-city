## 1. 新视觉基准

后续 UI/UX 升级以“明亮的深海秘仪档案馆”为主方向。

目标不是继续加深、加黑、加恐怖，而是在保留克苏鲁与深海氛围的同时，让界面更精致、华丽、自然、可长期使用。

核心关键词：

- 明亮档案桌
- 深海日光与冷雾
- 发光的秘仪档案馆
- 档案纸与纸张纤维
- 潮湿石材与浅色矿物面
- 氧化铜与旧金属边框
- 克制旧金仪式感
- 少量血红危险语义
- 非纯黑、非廉价恐怖
- 产品 UI，而不是营销海报

明确保留：

- 左侧深海金属导航。
- 中央明亮档案纸主工作区。
- 右侧 KP / 工具区可以更深，但不能是纯黑透明卡片。
- 背景可以有水下城市、雾和光，但正文必须放在清晰材质 Surface 上。

明确减少：

- 大面积 `bg-black/20`、`bg-black/40`、`rgba(0,0,0,0.x)` 主内容卡片。
- 泛用黑色玻璃拟态。
- 灰底灰字。
- 大面积血红恐怖背景。
- 过度圆角、装饰性大阴影、无意义发光。
- 只靠半透明遮罩保证可读性。

## 2. 视觉资产策略

优先使用 Codex 官方内置 image2 / 图像生成通道制作视觉草稿和纹理资产。暂时不使用 `cd-image2`。

生成资产只用于增强材质，不替代真实前端布局。

资产生成必须遵守 `2026-07-04-sunken-city-ui-asset-pipeline.zh-CN.md`：

- 先写资产规格卡。
- 再生成候选。
- 候选筛选通过后才能处理和入库。
- 入库后必须通过 CSS token 或组件 API 使用。
- 页面不得直接引用未登记的生成图片路径。

建议生成的纹理资产：

| 资产 | 用途 | 要求 |
| --- | --- | --- |
| 明亮档案纸纹理 | 主内容、长文、房间信息 | 低对比、可平铺、不影响文字 |
| 浅色湿石 / 石灰岩纹理 | 页面底层、次级面板 | 冷色、自然、无明显重复图案 |
| 氧化铜边框纹理 | 导航、工具台、重要面板边缘 | 铜绿、旧金、细节克制 |

| 暗釉陶瓷 / 深海石材 | 右侧工具区、弹层 | 深但不黑，有材质层次 |
| 旧金箔细纹 | 重要状态、稀有物、主操作 | 小面积使用，不做正文底 |

## 3. 材质化 Surface 系统

现有 `Surface` 不应继续只表达 `panel / solid / glass` 的透明度差异。下一轮应把它升级为材质层级。

建议新增或映射以下材质语义：

| 材质 | 用途 | 视觉特征 |
| --- | --- | --- |
| `archive` | 长文、档案、房间描述、论坛正文 | 明亮纸面、深色墨字、轻微纸纤维 |
| `limestone` | 普通页面区块、列表底 | 浅冷石面、柔和边界、低噪声 |
| `basalt` | 工具区、侧栏、导航 | 深海石材、不是纯黑 |
| `copper` | 重要容器、选中态、导航强调 | 氧化铜边、旧金线 |
| `relic` | 稀有物、收藏、位阶、印记 | 金属和纸面混合，有藏品感 |
| `danger` | 战斗、理智崩坏、不可逆操作 | 小面积血红，清楚但克制 |

原则：

- 主阅读区域优先 `archive` 或 `limestone`。
- 工具区优先 `basalt`，但文本对比必须稳定。
- `glass` 只保留给浮层、短提示、轻量弹出，不再作为主内容默认样式。
- 金色用于边框、分隔、状态、主操作，不用于低透明正文。
- 血红只用于危险、战斗、理智崩坏、不可逆操作。

## 4. 页面优先级调整

视觉迭代优先级提高后，执行顺序调整为：

### Phase 0：视觉材料与纹理资产

目标：先做材质基底，避免继续用黑透明卡片补页面。

任务：

- 为每种资产写规格卡，至少覆盖用途、槽位、尺寸、明暗档位、文字承载、禁止元素、目标体积和验收页面。
- 生成并筛选明亮档案纸、浅色湿石、氧化铜、深海冷雾、暗釉石材纹理。
- 建立纹理命名和引用路径。
- 将通过筛选的资产处理为 WebP，放入 `apps/web/public/ui-textures/`。
- 在 `tokens-v2.css` 中登记纹理 token。
- 不提交临时生成草稿，只提交明确被使用的 web 资产。

轻量验收：

- 纹理在 1440px 与 2560x1080 下不显得重复。
- 纹理不干扰 14px-16px 中文正文。
- 明亮纸面不发灰、不泛黄到廉价羊皮纸。
- 单张普通纹理目标小于 300KB，大背景目标小于 600KB。
- 素材无文字、符号、人物、触手、中心主体、强光斑和明显 AI 图像痕迹。

### Phase 1：材质化设计系统

目标：让页面可以用系统组件获得精致质感，而不是逐页手写。

修改重点：

- `apps/web/src/styles/tokens-v2.css`
- `apps/web/src/styles/system-v2.css`
- `apps/web/src/components/system/Surface.tsx`
- `apps/web/src/components/system/PageShell.tsx`
- `apps/web/src/components/system/ActionCard.tsx`
- `apps/web/src/components/system/ReadablePanel.tsx`

任务：

- 增加材质 Surface token。
- 增加 `archive / limestone / basalt / copper / relic` 映射。
- 建议 `Surface` 使用 `material` 维度承载材质，避免把材质塞进 `variant`。
- 收敛阴影，不使用宽泛软阴影制造假高级感。
- 建立明亮背景、平衡背景、暗色背景下的对应材质。
- 给按钮、标签、Tabs 建立一致的旧金 / 铜绿 / 血红状态。

轻量验收：

- 主内容区域不再像黑色透明卡片。
- 明亮背景下正文清楚。
- 暗色工具区不纯黑。
- 可交互状态明确。

### Phase 2：视觉样板页

目标：先做最能改变观感的页面，形成可复用范式。

优先页面：

1. 首页：从功能卡片入口升级为“城市档案台”。
2. 故事书 / 房间列表：从黑卡列表升级为“案卷柜与跑团档案”。
3. 无名集市：从普通商品列表升级为“遗物陈列与藏品账本”。
4. 黑水港：升级为“明亮深海港口小游戏台”。
5. 溺者之牌：升级为“明亮仪式牌桌与解牌档案”。

轻量验收：

- 一眼能看出新视觉方向。
- 页面仍是可用产品 UI，不像宣传海报。
- 移动端不堆叠成连续黑条。
- 样板页要证明 `archive / limestone / basalt / copper / relic / danger` 至少 4 种材质能在真实页面中共存。
- 样板页通过后，才允许批量迁移其他页面。

### Phase 3：长期留存体验

目标：把论坛、个人资料、位阶、印记、调查员档案统一为“秘仪档案馆”的长期资产。

重点：

- 论坛帖子像可归档文献，不像普通社交 feed。
- 个人资料像调查员档案夹。
- 位阶和印记像馆藏、证章、封印。
- 调查员列表和详情保持可读，同时增加纸面与藏品感。

### Phase 4：房间页分层重构

目标：把视觉升级带进核心跑团体验，但不破坏后端和 Socket 业务。

拆分方向：

- `RoomShell`
- `RoomStage`
- `RoomParticipantRail`
- `KpWorkbench`
- `PlayerConsole`
- `ObserverConsole`

硬边界：

- 不改房间后端业务逻辑。
- 不改 Socket 事件名。
- 不改骰点、战斗、私聊、生命周期写回。
- 不做结团后角色成长机制。
- 权限显示围绕 `myRole`、`myCapabilities`、`myBinding`、`lifecycle`。

视觉目标：

- PC / KP：明亮中央舞台 + 深色材质工具台。
- 移动端 / PL：聊天、骰点、自己角色状态优先。
- 观察者：低干扰只读视图。

### Phase 5：旧样式债务清理

目标：减少 AI 味和历史补丁。

重点清理：

- 大面积 `bg-black/*` 主内容容器。
- 随机硬编码颜色。
- 泛用黑玻璃卡片。
- 宽泛软阴影。
- 过度装饰性边框。
- 页面级重复补丁。

## 5. 官方内置 image2 使用规则

本 UI/UX 会话后续生成视觉草稿和纹理资产时：

- 优先使用 Codex 官方内置 image2 / 图像生成通道。
- 暂时不使用 `cd-image2`。
- 不要求用户提供 chedankj `image` 组 key。
- 概念图用于方向确认。
- 纹理图用于真实前端资产。
- 生成资产进入项目时必须经过筛选、命名、压缩和尺寸控制。
- 生成资产必须满足资产规格卡；不满足规格的图即使好看也不入库。
- 同一材质至少生成 2 个候选，优先选择更低对比、更可读、更可复用的版本。

建议 image2 prompt 原则：

- 描述真实材质，不描述“漂亮 UI 背景”。
- 明确要求 seamless / low contrast / text-safe / production texture。
- 明确避免 cartoon、gore、purple gradient、bokeh blobs、generic black glass。
- 纹理生成优先方图或宽图，按真实使用位置裁切。

禁止 prompt 方向：

- “beautiful UI background” 但没有槽位约束。
- “cinematic poster”“dark horror poster”“concept art”。
- 大面积黑玻璃、紫色渐变、血红背景、bokeh 光斑。
- 带文字、符号、徽章主体、角色、怪物或中心物体的纹理。

## 7. 轻量验收标准

除非用户主动要求，不做深度测试。

每阶段最多做：

- 目标页面手动截图或轻量截图。
- 375px 手机。
- 1440px 桌面。
- 2560x1080 超宽。
- 必要时运行 `npm run typecheck` 或 `npm run build`。

视觉验收：

- 整体比现状更明亮。
- 主内容像档案纸、石材或金属材质，不像透明黑卡。
- 文本不灰、不糊、不靠黑幕。
- 装饰边框不压过内容。
- 血红不超过单屏主要 UI 的小比例。
- 移动端主任务优先，不为了装饰牺牲操作。

逻辑验收：

- image2 资产有规格卡。
- 入库资产有固定命名。
- CSS 通过 token 引用资产。
- 新页面不直接写未登记图片路径。
- 主内容不继续依赖 `bg-black/20`、`bg-black/40` 或透明黑卡。
- 房间页相关按钮仍以 `myCapabilities` 为主，不从 `isCreator` 猜权限。

## 8. 已确认样板页基准

2026-07-04，用户已确认“故事书 / 房间列表”当前视觉草稿可作为后续迭代升级方向。

该样板页是当前 UI/UX 重构的第一张真实前端基准，不再只是概念图。后续页面迁移时应优先继承它已经验证过的视觉语言，而不是重新发散。

### 8.1 已确认的视觉语言

- 主内容使用明亮档案纸和浅色湿石，不回退到黑色透明卡片。
- 页面背景保留深海城市与冷雾，但正文必须落在清晰 Surface 上。
- Header 使用深海冷雾材质、旧金线条和仪式性装饰，但装饰不能变成无意义堆叠。
- 主行动按钮使用旧金主体 + 暗血红尾色 / 流光，不再使用金色配绿色。
- 血红在这里作为“秘仪张力”的少量配色，不扩大成危险背景。
- 空状态可以使用金色仪式素材居中铺底，但文字、图标、按钮必须在上层清楚可读。
- 素材纹理要明显到能感知材质，但不能遮盖或污染内容。
- 不接受没有功能解释的中间装饰块、拉伸模糊素材、科技网格感和廉价 AI 黑玻璃。

### 8.2 当前真实落地点

| 槽位 | 当前方向 | 后续复用规则 |
| --- | --- | --- |
| 故事书 Header | 深海冷雾 + 金色太阳弧线 + 左侧仪式标记 | 可复用为“档案馆 Hero Band”，但每页应按内容调整装饰密度 |
| 主内容空状态 | 明亮档案纸 + 居中金色仪式素材 | 适合空状态、账本、收藏册，不适合普通正文背景 |
| 快速进入面板 | 明亮纸面输入 + 金色按钮 | 可复用为轻量表单入口 |
| 当前索引 | 浅色 Surface + 金色月弧素材 | 适合统计、摘要、收藏索引 |
| 主按钮 | 旧金 + 暗血红 | 适合主行动；危险操作仍需更明确血红语义 |

### 8.3 下一阶段执行原则

下一步不是继续在故事书单页上无限微调，而是把已经确认的样式抽象成可复用规则：

1. 抽象“金色 + 暗血红”主行动按钮样式。
2. 抽象“档案馆 Hero Band”结构。
3. 抽象“仪式素材空状态”结构。
4. 整理手工金箔素材的入库记录和使用规则。
5. 再选择下一个页面推广，优先个人资料 / 调查员档案夹或无名集市。
