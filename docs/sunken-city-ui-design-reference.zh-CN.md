# 沉没之城通用 UI/UX 设计参考

日期：2026-07-09  
状态：页面改造通用规范  
适用范围：房间列表页、房间系统 PL 端、聊天/日志类页面、资料/管理/工具类页面，以及后续非房间页面的视觉统一改造。

## 1. 目标

把当前已经基本定版的 `rooms` 页面、房间系统 PL 端左侧栏、右侧栏、聊天区域和素材体系整理成一套可复用规则。后续页面改造时，不再临时重做一套视觉，而是沿用“沉没档案室”的统一设计语言。

核心方向：

- 不是黑色透明后台面板。
- 不是廉价大面积纹理。
- 不是泛用 AI 奇幻 UI。
- 是偏白羊皮纸、深绿玄武岩、氧化铜金线、档案卡片、仪式感字体共同组成的“沉没档案室”。

## 3. 页面类型

### 3.1 索引/列表页

适用：房间列表、角色列表、消息中心、论坛列表、通知列表。

结构建议：

- 顶部：页面标题、简短说明、主操作按钮。
- 中部：筛选条 + 列表卡片。
- 右侧：快速进入、最近记录、状态摘要。
- 背景：全站背景透出，但正文区域必须有浅色纸面承托。

视觉参考：`RoomListPage` 的“故事书 / Story Gateway”结构。

### 3.2 工作台/详情页

适用：房间 PL 端、角色详情、个人资料、调查记录、复杂工具页。

结构建议：

- 左侧栏：身份、上下文、当前对象摘要。
- 中央区：主要阅读/操作内容。
- 右侧栏：工具、状态、快捷操作、最近结果。
- 底部：如有输入或工具条，必须和中央正文分割独立。

视觉参考：房间 PL 端“调查员档案 + 聊天区 + 案板/工具区”。

### 3.3 聊天/日志/记录页

适用：房间聊天、私聊、通知详情、系统记录、跑团日志。

结构建议：

- 中央使用偏白做旧羊皮纸。
- 消息卡片使用同源纸面材质，不用明显渐变。
- 消息间距紧凑，姓名和时间清晰。
- 骰点、状态、结果类信息放在右侧小结果框，和正文并列。
- 系统提示尽量保持一行，不额外撑高记录。

## 4. 布局规则

### 4.1 三栏页面

桌面端推荐：

- 左栏：`14rem - 17rem`，承载身份、档案、参与者、上下文。
- 中栏：自适应，占据主要阅读空间。
- 右栏：`20rem - 24rem`，承载工具、操作、最近结果。

原则：

- 左右侧栏边缘应与顶部栏或页面主容器对齐。
- 中央区优先保证可读性，不为了装饰压缩正文。
- 底部输入区与聊天/正文区域分离，不能被包进同一张大卡片里。
- 不要在大卡片内再塞一层大卡片；只有列表项、工具按钮组、弹窗可以使用卡片嵌套。

### 4.2 左侧栏

左侧栏的关键词是“档案纸”和“人物上下文”。

建议：

- 使用浅色档案纸材质。
- 自上而下有轻微透明渐隐，让全站背景在底部透出。
- 磨砂度低，纹理可见。
- 内部卡片平面化，弱阴影，细铜金线。
- 数值信息用更高可读性的数字字体，避免花体影响识别。

不建议：

- 黑色玻璃栏。
- 高亮大阴影浮卡。
- 把装饰图大面积铺满。

### 4.3 中央内容区

中央区的关键词是“可读纸面”。

建议：

- 使用偏白做旧羊皮纸材质。
- 文本颜色接近深褐/黑褐。
- 纹理要可见，但不能干扰文字。
- 消息、日志、记录卡片去掉重渐变，主要靠纸面纹理、细边线和留白区分。
- 空状态可以使用细线图标和短文案，不要放大段说明。

### 4.4 右侧栏

右侧栏的关键词是“工具台”和“低磨砂玻璃”。

建议：

- 外层使用深绿玄武岩/氧化铜暗材质。
- 内部小区域使用低磨砂玻璃感，透明度比黑色卡片更高。
- 按钮透明、金边、轻微底色，不再额外叠纹理。
- 操作组平面化，减少立体投影。

适用内容：

- KP 工具台。
- PL 快速行动。
- 最近检定。
- 当前案板。
- 状态摘要。

## 6. 材质分层

### 6.1 主纸面

用途：正文、聊天、日志、输入区、主要阅读卡片。

建议组合：

- 底图：`room-v6-aged-parchment-white.webp`
- 底色：暖白、浅羊皮纸色。
- 边缘：极轻脏污和内阴影。
- 立体感：弱。

视觉目标：

- 远看是干净白纸。
- 近看有做旧纤维。
- 文字对比足够强。

### 6.2 档案纸

用途：左侧栏、角色档案、身份摘要、列表页侧栏。

建议组合：

- 底图：`room-v6-archive-paper.webp`
- 边框：低对比铜金线。
- 卡片：平面化，少量投影即可。

视觉目标：

- 像一组被整理好的调查档案。
- 信息密度可以高，但不能拥挤。

### 6.3 深色工具台

用途：右侧工具栏、KP 操作台、暗色快捷操作面板。

建议组合：

- 底图：`room-v6-console-basalt.webp`
- 内层：半透明深绿/墨绿玻璃。
- 边线：暗金。
- 按钮：透明金边。

视觉目标：

- 像沉在水下的石质工具台。
- 不能变成黑色透明后台。

## 7. 字体规则

中文：

- 优先使用 `Source Han Serif SC` / `Source Han Serif CN` / `Noto Serif CJK SC` / `思源宋体`。
- 页面标题、房间名、角色名使用更高字重。
- 正文使用常规字重，确保阅读舒适。

英文和数字：

- 优先使用更有仪式感的衬线字体，例如 `Cinzel`、`Cormorant Garamond`、`EB Garamond`、`Georgia`。
- 大号数字可以使用衬线字体增强仪式感。
- 小号数值、生命值、技能值要优先可读，必要时使用清晰数字栈。
- 数字列表建议使用等宽数字排布，避免跳动。

禁止：

- 负字距。
- 跟随视口宽度无限缩放的字体。
- 低透明度金字正文。
- 过小、过花的数值字体。

## 8. 色彩规则

推荐角色：

- 暗金：主强调、边线、仪式状态、重要按钮。
- 血红：发送、危险、战斗、警示、不可逆动作。
- 海绿/青绿：在线、连接、同步、次级状态。
- 暖白/羊皮纸：正文承托。
- 深绿/玄武岩：工具区、顶部栏、右侧栏。

禁止倾向：

- 大面积纯黑透明。
- 大面积血红装饰。
- 单一深蓝/深灰后台风。
- 大面积紫蓝渐变。
- 卡片之间只靠强阴影区分。

## 9. 通用组件用法

优先沿用现有系统组件：

- `PageShell`：页面外壳、标题区、右侧 aside。
- `Surface`：通用材质面板。
- `ReadablePanel`：正文阅读容器。
- `DataCard`：数据卡片。
- `ActionCard`：操作入口。
- `Button`：标准按钮。

建议：

- 页面级容器用 `PageShell`。
- 浅色正文容器优先用 `Surface` / `ReadablePanel` 并使用 archive/paper 类材质。
- 工具按钮使用图标 + 简短文字。
- 有现成 lucide 图标时优先使用 lucide。
- 卡片圆角不超过 8px；按钮圆角一般 4px - 6px。

## 10. 交互规则

按钮：

- 每一个可点击按钮都必须有明确反馈。
- 禁用态要能看出不能点击，但不能低到看不清文字。
- 工具按钮优先小而清晰，避免占满整行。

抽屉/菜单：

- 多功能工具不要全部常驻展开。
- 常用功能常驻，低频功能放入抽屉或菜单。
- 私聊类一对一功能应尽量融入聊天框目标选择，不再制造独立入口。
- 子房间是多人支线聊天/分组剧情，应该保留独立入口。

聊天：

- 输入区和消息区分离。
- 快捷短语、投骰、发送按钮属于输入工具条，不属于消息列表。
- 骰点结果与消息正文并列显示，避免挤压正文。

## 11. PL/KP 角色差异

PL 页面：

- 重点是“我的角色、我的行动、我的信息”。
- 左侧放调查员档案、生命/理智/魔法、同行者。
- 中央放聊天和当前场景。
- 右侧放当前幕、同步状态、快速行动、最近检定。
- 视觉上更偏“个人档案纸 + 少量工具台”。

KP 页面：

- 重点是“主持、调度、场景、NPC、投骰、结算”。
- 右侧工具台权重更高。
- 工具需要系统整理，入口少而明确。
- 视觉上更偏“守密人工具台 + 档案记录”。

其他页面改造时：

- 如果页面是个人/资料/角色，靠近 PL。
- 如果页面是管理/工具/调度，靠近 KP。
- 如果页面是列表/索引，靠近 rooms 页面。

## 12. 移动端原则

移动端不要直接压缩三栏。

建议：

- 中央内容优先显示。
- 左侧身份信息折叠为顶部摘要或抽屉。
- 右侧工具折叠为底部工具条或抽屉。
- 输入区固定在底部时，必须避免遮挡消息。
- 触控按钮尺寸优先保证可点，不保留桌面端过密布局。

## 13. 改造检查清单

每个新页面或改造页面完成后，至少检查：

- 是否使用全站背景或同源房间背景。
- 是否避免黑色透明卡片。
- 主阅读区是否有偏白纸面材质。
- 右侧工具区是否使用深色材质而不是普通黑玻璃。
- 左侧档案区是否有浅纸面、弱阴影、清晰层级。
- 大容器角饰是否只用于大容器。
- 字体是否统一为思源宋体/衬线体系。
- 数字是否足够清晰。
- 按钮尺寸是否一致。
- 图标和文字是否垂直居中。
- 文本是否没有溢出、重叠、被图案遮挡。
- 低频工具是否没有挤占主区域。
- 移动端是否有明确折叠方案。

## 14. 推荐改造顺序

后续非房间页面建议按以下顺序统一：

1. 角色详情页：最适合沿用 PL 左侧档案 + 中央纸面 + 右侧状态栏。
2. 消息中心：最适合沿用聊天/日志纸面。
3. 通知中心：沿用列表页 + 记录卡片。
4. 个人资料页：沿用个人档案纸。
5. 好友页：沿用索引/列表结构。
6. 论坛页：沿用故事书/档案索引结构。
7. 钓鱼、梦境等玩法页：按功能性质选择“PL 个人档案”或“KP 工具台”方向。

## 15. 简短准则

应该做：

- 用材质建立世界观。
- 用纸面保证阅读。
- 用暗金线建立秩序。
- 用右侧栏收纳工具。
- 用左侧栏说明身份和上下文。
- 用中央区承载核心操作。

不应该做：

- 为每个页面重新发明一套 UI。
- 把所有工具按钮都塞在同一行。
- 用黑色透明卡片假装高级。
- 用大面积纹理压过文字。
- 用强阴影制造廉价立体感。
- 把装饰图当作普通背景反复铺满。

## 16. 给后续页面的落地判断

如果一个页面不知道该怎么改，先回答三个问题：

1. 用户来这个页面主要是阅读、操作，还是管理？
2. 页面最重要的信息应该放在左侧、中央，还是右侧？
3. 这个页面更像 PL 的个人档案，KP 的工具台，还是 rooms 的故事索引？

答案确定后，再选择对应结构和材质，不要先从颜色或装饰开始。
